# CLAUDE.md — working rules for garnish

garnish is a Rust CLI that renders the Claude Code status line, built
entirely by Claude across many sessions. This file is *how to work on this
codebase*: rules, not history. The stories behind the rules are in
`WORKLOG.md` under their dates. It is host-neutral. Read it, then `PLAN.md`.

## Hosts

The SessionStart hook runs `scripts/session-host.sh`, exports `SESSION_HOST`
(`sprite`, `popos`, `macos`, `ci`, `unknown`) and prints host context (all
of `SPRITE.md` on a Sprite). `scripts/setup.sh` reads the same variable.

- **Nothing about a personal machine goes in this repository** (signing,
  accounts, keys, tool management): that lives in the user-level
  `~/.claude/CLAUDE.md`.
- Sprite facts go in `SPRITE.md`. Host trouble is fixed on the host, never
  recorded in `PLAN.md` or `WORKLOG.md`.

## Session protocol

1. Read `PLAN.md`: the first unchecked item of the open phase, else the
   backlog.
2. Small commits; `make check` before every commit (`make setup` if a tool
   is missing; it is idempotent).
3. Before ending: tick `PLAN.md`, add or extend today's `WORKLOG.md` entry,
   commit, push. Never leave the tree red.
4. **Push early and often**: after every phase, every review-fix batch,
   every hour.
5. **Branches and PRs.** `main` is protected (PRs only, signed commits,
   green CI). Work on `review/<date>`, `phase-N/<topic>` or `docs/<topic>`
   and open a PR against `main`; merge only when the user asks. Multi-part
   work is one **`gh stack`** chain, one layer per concern
   (`phase-N/<concern>`), submitted as drafts (`gh stack submit --auto`),
   flipped to ready once CI is green and the phase's review is done. Edit a
   concern in its own layer, then `gh stack rebase --upstack`. Resolve
   conflicts in generated files (`docs/`, `examples/`, `tests/golden/`) by
   regenerating (`UPDATE_DOCS=1`, `UPDATE_GOLDEN=1`), never by hand. Drive
   `gh stack` non-interactively only (`--json`, `--auto`, `--yes`). Whole-stack
   review fixes go in `review/<date>-<concern>` layers on top.
6. **Signed commits and tags, always.** If signing fails, stop and report;
   never `--no-gpg-sign`.
7. **Edit files with Read/Edit/Write**, never Bash heredocs, `sed` or
   Python one-liners (they bypass the harness's file tracking; one lost a
   write here).
8. **Use the rust-analyzer LSP tools** when available: diagnostics after
   edits, definitions and references before renaming.
9. **Stop and ask** when a decision is the user's: a design change against
   `SPEC.md`, a new dependency, behaviour the spec leaves open. Do not widen
   scope.

## Phase protocol

**Starting a phase.** Compare `SPEC.md` and `PLAN.md` with the code. If they
disagree, update the documents first, with the reason, then code.

**Finishing a phase.**

1. Validate the goals (tests, `make check`, `preview` when rendering
   changed).
2. Update `PLAN.md`, `WORKLOG.md`, `SPEC.md` (with why), this file (how to
   do things), `README.md`/`docs/guide.md` (what users need).
3. If code was written, spawn an **adversarial review subagent** to attack
   the changes: broken behaviour, subtle bugs, lint escapes, spec drift,
   missing tests. Give every subagent **its own worktree** (`isolation:
   "worktree"`) and a brief forbidding git commands that touch the working
   tree (`stash`, `checkout`, `reset`).
4. Every real bug gets a unit test, and an integration or golden test when
   it is user-visible.
5. Commit and push.

## Toolchain

- **Nightly Rust** via rustup (`rust-toolchain.toml`, rolling `nightly`,
  with `rustfmt`, `clippy`, `rust-analyzer`, `rust-src`). `make setup`
  installs it plus `cargo-nextest`; `ARGS=--bench` adds `hyperfine`, `jq`;
  `--all` adds `watchexec`. If a nightly breaks the build, pin
  `channel = "nightly-YYYY-MM-DD"` and note it in `PLAN.md`.
- **CI installs a fresh nightly; a session's may be days older.** When CI is
  red on a lint that passes here, `rustup update nightly` first, then one
  `cargo clippy --all-targets` finds every site (including `#[cfg(test)]`).
  If another worktree is using the toolchain, install a dated one beside it
  and run `cargo +nightly-YYYY-MM-DD clippy --all-targets`. A PATH note from
  `make setup` is fixed on the host, never in the repository.
- Edition 2024. `cargo nextest run` (the cache/worker tests need its serial
  groups), `cargo test --doc`, `cargo bench`, `./bench/run.sh`.
- **`make check` is not all of CI**: rustdoc `-D warnings` runs only in
  `scripts/ci.sh`, so run `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps`
  before pushing. Never gate a commit on a pipe (`make check | head &&
  git commit` commits on red); log to a file and test the status.
- **The payload is read field by field.** A scalar field takes
  `#[serde(deserialize_with = "or_none")]`, a struct-typed one
  `object_or_none`. A new field also goes into `FULL` in `payload.rs`,
  which the sweep test feeds every wrong JSON type.

### Testing tricks

- A test that measures an age reads the clock *after* the event.
- A test running a logged spawn by hand passes `--lock-held` on Linux.
- Reftable fallback: a git without `--ref-format=reftable` ignores an empty
  `.git/reftable/tables.list`, which simulates it.
- Before/after benchmark: temporary commit, `git checkout HEAD~1 --
  <files>`, bench, restore, `git reset --soft HEAD~1`. On a noisy host use
  `valgrind --tool=callgrind` instruction counts; gate `make bench` on a
  quiet machine only.
- `std::io::pipe()` with the reader dropped gives a child an unread stderr
  (`tests/cli.rs::piped_with`).
- A layout fuzz must include `custom` frames. "A line is exactly the box"
  holds only with `fill = true` or on a boxed line; otherwise it is at most
  the box.
- Never edit a source while a background `make check` runs.
- A PATH-shim `git` that logs `CALL $*` and the asked-for variables sees a
  child's arguments (`recorded_git_calls`); never log the whole
  environment.
- Logic that depends on the platform's managed settings file takes paths
  as parameters and is unit-tested pure (`demote_hooked`, `layer_of`,
  `own_settings_files_in`, `chain_target`, `managed_env` over `ChainFile`s).
  Each case must set up the input its guard exists for.
- **macOS temp paths are ~60 characters** (Linux ~15): before pushing a
  test that bounds a message or names a file, run the suite once with
  `TMPDIR` longer than 100 characters.
- A scratch export of the crate sharing `CARGO_TARGET_DIR` clobbers the
  checkout's artifacts; give it another `version`. `benches/tick.rs` reads
  git at `CARGO_MANIFEST_DIR`, so compare builds made the same way.

## Commands

```
make setup        # toolchain + nextest + shellcheck (ARGS=--bench|--all for more)
make check        # fmt --check + clippy -D warnings + nextest + doctests
make lint         # fmt --check + clippy
make test         # cargo nextest run && cargo test --doc
make docs         # regenerate docs/ and examples/ from the module schemas
make bench        # hyperfine budget gate
make watch        # watchexec: lint + test on every save
make install      # cargo install --path . --locked
./scripts/ci.sh   # all of the above plus --locked, shellcheck,
                  # scripts/test-scripts.sh and rustdoc -D warnings
```

CI (`.github/workflows/ci.yml`) runs `scripts/setup.sh` + `scripts/ci.sh` on
Linux and `make check` + `scripts/test-scripts.sh` on macOS (the only
coverage of Mac-only paths) for pushes to `main`, tags and PRs; the bench
job is manual. **Every action is pinned to a full commit SHA** with a
`# vX.Y.Z` comment (Renovate bumps them); a downloaded tool is pinned and
sha256-checked (`setup.sh`: bump the cargo-nextest version and its three
hashes together). On failure `scripts/ci-annotate.sh` turns test, clippy and
rustfmt failures into check-run annotations.

## Claude review

`.github/workflows/claude-review.yml` reviews a PR **on demand only**:
`justanotherspy` comments `@claude` or adds the `claude-review` label, on a
PR opened by `justanotherspy` that is open and not a draft. Never on push.
It authenticates by **workload identity federation** (no API key); the
rule's subject pattern must use GitHub's immutable subject with numeric
IDs (`repo:justanotherspy@4822513/garnish@1357344340:…`).

Rules (history: `WORKLOG.md` 2026-09-17, -19, -25):

- **The job collects the review's inputs in job shell** into
  `$RUNNER_TEMP/review/` (`pr.md`, `commits.md`, `diff.patch`,
  `diffstat.txt`, `files.txt`, `checks.txt`); the prompt points `Read` and
  `Grep` at them. The diff is against the PR's own base (a stacked layer is
  reviewed alone); the checkout is `fetch-depth: 0` at the PR head.
- **The prompt is short**: the files, the six review points (each citing
  its `CLAUDE.md` rule), how to post, terse comments, always the summary.
- **Remove capabilities; don't instruct against them.** A tool left off
  `--allowedTools` is still callable, so `--disallowedTools` names `Task`,
  `Skill`, `Workflow`, `CronCreate`, `ScheduleWakeup` and the edit tools
  (`scripts/test-scripts.sh` checks it). `Bash` is allowed whole (an
  allowlist of verbs cannot work: prefix matching, and compound commands
  are refused) and is safe only because of what it can reach: the action
  gets the job's own `github_token` (`contents: read`), only the owner's
  comments reach the prompt (`include_comments_by_actor`), and
  `allowed_non_write_users: justanotherspy` turns on the action's
  isolation (bubblewrap, environment scrub, credential helper). Never set
  `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` alone.
- **Turns are the binding constraint**: cap 100, Sonnet 5 at `--effort
  high`. Keep notes above the `claude_args` block, never inside it.
- `track_progress: true`; the summary is written into the tracking comment
  (`update_claude_comment`) and is its last write with no `- [ ]` left.
- **A green action proves only that the job ran.** The last step runs the
  *base branch's* `scripts/review-denials.sh` (fetched via the contents API,
  never from the untrusted checkout) over
  `$RUNNER_TEMP/claude-execution-output.json` and fails on any permission
  denial or a missing summary; a failed fetch fails the step; a run with no
  execution file is reported and exits 0. It prints denied commands' verbs
  only, never arguments. Never enable `show_full_output`.
- **`concurrency` belongs to the job, never the workflow**, and the job
  `if` excludes bot authors.
- **Keep a change to the review workflow in its own PR.**

## Release process

A release is a signed `vX.Y.Z` tag on `main`; `release.yml` does the rest
and stops once, before publishing the Homebrew cask, for Daniel's approval.

1. **Release PR** (`release/<version>`): bump `version` in `Cargo.toml`
   (`make check` updates `Cargo.lock`), turn `## Unreleased` in
   `CHANGELOG.md` into `## X.Y.Z — YYYY-MM-DD`, `make check`, merge.
2. **Tag** the merged commit with the section as its message:
   ```
   git switch main && git pull
   scripts/changelog-section.sh X.Y.Z | git tag -s vX.Y.Z --cleanup=verbatim -F -
   git push origin vX.Y.Z
   ```
   (`--cleanup=verbatim`: the default drops lines starting with `#`.)
3. **The workflow**: `verify` (annotated tag naming the crate version,
   `Cargo.lock` agrees, on `main`, CHANGELOG section present, no
   `## Unreleased`; the `release` environment exists with a required
   reviewer, no admin bypass, a custom deployment policy) → `release` (a
   GitHub pre-release) → `build` (`garnish-<target>.tar.gz` + `.sha256` for
   x86_64/aarch64 Linux and macOS; rustup only, no cache) → `render` (the
   cask from the template, printed, `brew fetch`ed, kept as the `cask`
   artifact) → **`publish` waits for Daniel's approval** (read the render
   log first), then pushes `Casks/garnish.rb` to
   `justanotherspy/homebrew-tap` with an octo-sts token → `promote` marks
   the release *Latest*. A settings or transient failure is re-run in the
   same run; anything needing code is a new version (a tag is never moved).
4. **Repository state it needs** (settings, before the first tag): the
   `release` environment with Daniel as required reviewer, `v*` tags only,
   admin bypass off; the octo-sts app on the tap with
   `.github/chainguard/garnish.sts.yaml` trusting
   `repo:justanotherspy/garnish:environment:release`; a `v*` tag ruleset
   limited to Daniel with required signatures.

**The cask template is declarative, not Ruby**: `postflight_steps` (the
`Homebrew::InstallSteps::DSL` vocabulary: `run`, `on_macos`), the staged
binary is `"{{staged_path}}/garnish"` (a template token, not
`#{staged_path}`), and `url` is bare (no `verified:`). Homebrew 7.0 raises on
the deprecated forms under `HOMEBREW_DEVELOPER`. `brew fetch` never stages
or installs, so check the quarantine strip by hand at the first release's
approval gate: `brew install --cask ./garnish.rb`, then `xattr -p
com.apple.quarantine "$(brew --prefix)/bin/garnish"` must say
`No such xattr`.

## Style: strict lints, never panic

`Cargo.toml` denies `clippy::pedantic`, `clippy::nursery` and every panic
path (`unwrap_used`, `expect_used`, `indexing_slicing`,
`arithmetic_side_effects`, `unreachable`, `unimplemented`,
`unchecked_time_subtraction`, `todo`, `string_slice`, `panic_in_result_fn`,
`panic`, `exit`, `as_conversions`). `clippy.toml` allows
unwrap/expect/panic/indexing in tests only.

- No `unwrap()`/`expect()` outside tests: `?`, `unwrap_or`, `map_or`,
  `let-else`. An infallible `Result` is taken apart with `let Ok(x) = …;`.
- No indexing: `.get(i)`; never slice strings (iterate chars, see
  `ansi::truncate`).
- No `as`: `From`/`TryFrom`; float→int through the helpers in `num.rs`.
- Non-constant arithmetic is `checked_*`/`saturating_*`/`wrapping_*`. Also
  in a helper inside a test module that is not itself a `#[test]`.
- `clamp` panics on inverted bounds; with run-time bounds use
  `.max(lo).min(hi)`.
- `main` returns `color_eyre::Result<ExitCode>`; a `cli::Quiet` error exits
  1 with no report. **`render` never exits non-zero**: errors become a dim
  `⚠ garnish: …` row on stdout and a note on stderr.
- `#[allow(clippy::…)]` only with a one-line justification above it.
  Integration tests carry a crate-level `#![allow(…)]` with that comment.
- `unsafe_code` is forbidden, so a unit test cannot set an environment
  variable; to keep a render from spawning, hold a live lock.
- Combinator pipelines over `if let` towers.
- Shell scripts pass `shellcheck` and run on GNU and BSD userlands.

## Comments and documentation

- Every file has a `//!` doc saying what it owns; every `pub` item has a
  `///` doc (`missing_docs`). Docs say what and why, in rustdoc form.
- Inline comments only for the non-obvious (an invariant, a quirk, an
  ordering, a spec reference). No narration, no "changed X", no commented
  code. Deleting fluff is part of finishing a phase.
- `lib.rs` makes a module `pub` only when `main.rs`, `tests/` or `benches/`
  use it. A public doc names a `pub(crate)` item as a code span, not an
  intra-doc link.

makes no network calls.

## Architecture in one breath

stdin JSON → `Payload` → `Config` (TOML + presets) → each `[[row]]`'s
modules render `Vec<Segment>` from the payload or their cache file →
`layout` places columns on lines at `$COLUMNS − 4 − padding`
(`Config::width`) → stdout. A cached module past its TTL spawns a detached
`garnish refresh` worker and keeps the last value; only `stale_after` TTLs
overdue does it dim with `⟳`. **No child process on a warm tick.**
`garnish setup` (`src/setup/`) is never on the render path: it edits the
config as a table, previews through `render::render_tree_at` and installs
through `install::Steps`.

## Conventions

### Schema and config

- **The module schema is the single source of truth** for every option,
  icon, colour and preset value. Adding an option: schema → render →
  `make docs` → `UPDATE_GOLDEN=1 cargo nextest run` → commit `docs/`,
  `examples/`, `tests/golden/` (`tests/docs_sync.rs` fails on drift). An
  option that sizes an allocation or loop carries `.max(…)`. Rules beyond
  the kind go on `OptSpec.rule` (`Rule::Ascending`, `Rule::TimeZone`), never
  in the render.
- **Common options** (`label`, `prefix`, `suffix`, `hide_when_empty`,
  `max_width`) are `COMMON_OPTS` in `schema.rs`; a sixth needs the spec, a
  field on `Overrides`, an arm in `set_common`, and a `ModuleCfg` field with
  arms in `resolve` and `common` (the tripwire
  `no_schema_redeclares_a_common_key_and_every_common_key_is_stored`
  checks). **Hand-parsed** keys (`enabled`, `preset`, `refresh`, `hide`): a
  fifth needs `HAND_PARSED`, `parse_overrides`, `docs::write_modules`,
  `module_reference` and `setup::form::module_fields`.
- **Every word list has one source**: a config enum implements
  `config::Vocab` (`ALL`, `name`) and joins the `vocab!` list; table key
  lists are the `*_KEYS` arrays. Tripwires check both.
- `config/` is split by concern: `load`, `rows`, `frame`, `overrides`,
  `read`, `vocab`.
- **Tightening a rule breaks configs already written.** Check what
  `examples/garnish.toml` on `main` contains first (`separator_frames = []`
  is in every generated config). A generator changed to dodge its own new
  error means the rule is wrong.
- A **gallery preset** is a promise `tests/presets.rs` checks (name,
  summary, an uncut width at three instants, promised motion, ticker slide
  = `ticker_step`). Register it in `gallery::FILES` (alphabetical), run
  `make docs`. Write frame glyphs as TOML escapes (`"\U000025D0"`) and check
  the bytes with `od -c`: the Edit/Write tools decode `\uXXXX` into the
  glyph.

### One helper per rule

New code uses the existing helper; each of these was once written out per
call site and drifted. **Fix the shape, not the example.**

| rule | helper |
|---|---|
| the config file a writing command writes | `config::write_target` (explicit → the `--config` the `statusLine.command` passes → `locate` → default) |
| the config a looking command reads (`config check/show`, `preview`, `doctor`) | `config::read_target` (same, no default) |
| `GARNISH_CONFIG` from a hand command | `config::hand_explicit` via `cli::explicit_or_quiet`; managed hook: `hand_managed` |
| a config named by a checkout's own settings | `config::Checkout`: refused, never followed |
| `GARNISH_CONFIG` on the tick | `explicit`: absolute taken as is, relative ignored; a settings `env` block's value is followed by `command_target` (`env_target`) |
| reading a settings file | the tick: `claude_settings::read_file` (stops at 1 MiB); hand commands: `read_file_up_to` (whole); the tick and workers use `locate` alone |
| the managed layer that decides a config | `chain_files` (`chain_files_rewriting` for `install`); `doctor` lists via `config::managed_layer`, loads via `config::load_exactly` |
| splitting a `statusLine.command` | `install::shell_words`, `Word::expanded` (never `Path::join`) |
| stderr on the render path | `debug::stderr_line` (the macros only in `cli.rs` and `setup/`) |
| user settings directory | `claude_settings::user_dir` (`CLAUDE_CONFIG_DIR` first) |
| boolean env hooks | `claude_settings::env_flag` |
| `NO_COLOR` | `config::no_color_env` |
| a refusal | `cli::refusal` (one stderr line, `Quiet`) |
| any file read on a timer | `claude_settings::read_regular` (regular files only, capped) |
| a module context | `render::context` |
| a path in an env variable | `config::env_path` (empty = unset; `GARNISH_MANAGED_SETTINGS` is the documented exception), `claude_settings::home_dir`, `config::xdg_path` (must be absolute) |
| rewriting a file | `install::replace_file` (backup, temp, `rename`); refuse an unparsable file first (`install::merge`, `config::syntax_error`) |
| module glyphs and marks | `modules::lead`/`lead_only`/`badge`/`glyph_prefix`/`close_up`/`show_icon_opt`, `util::cut_name`, `util::bar_opt`, `util::added_removed`, `IconSet::ellipsis`/`stale_glyphs`/`placeholder` |

- The render matrix in `render.rs` checks every module × preset × icon set ×
  `max_width` × fixture. A unit test scans `src/modules/*.rs` for keys read
  by name that no schema declares (`KEY_CALLS`, `IMPLIED`, `DEFINED` in
  `modules/mod.rs`); a test build also panics on any undeclared read.
- **A glyph repeated cell by cell is one cell** (`schema::ONE_CELL_ICONS`:
  `fill`, `empty`, `marker`; `marker` may be blank). Applies to
  `<key>_frames` too.
- `Segment.text` is private; text enters through
  `Segment::plain`/`styled`/`with_text`/`push_str`, which strip escapes.
- The module set is fixed (25 ids in `SPEC.md`) plus `text.<name>` (static
  text only). No module that runs anything.
- Every time read goes through `time::now()`. Every env hook has a `*_ENV`
  constant, is in `doctor::TEST_HOOKS` and in SPEC § 9 Test hooks (a test
  scans for `GARNISH_*` literals).
- A cached module outside the repo group (`account`) goes through
  `Ctx::cached`, gated by `Clock.workers`; a module reading the settings
  chain gets its docs sample from `Clock.settings_keys`.

### Setup screen

- Generated from the same schema: every `OptSpec` kind and top-level key
  has a form row; pickers come from `modules::SCHEMAS` and
  `icons::suggestions` (Nerd glyphs as `\u{…}` escapes; no empty
  suggestion).
- The draft is the file's `toml::Table` (`setup::Draft`), never a resolved
  `Config`. `Draft::resolved` runs the real parser; `App::try_set` refuses
  what it would report. A form lists only keys the parser takes there plus
  any the file sets; each picker entry must parse.
- Undo is by construction: `App::input` brackets every handled key or
  click. `Draft::is_dirty` compares tables. `toml::Map::remove` keeps order.
- `setup::app` is `app.rs` plus `app/*.rs`, one file per screen.
- Snapshot goldens under `tests/golden/setup/`, listed in `tests/setup.rs`;
  `setup::for_test` pins clock and home. Cheapest bug hunt: an out-of-tree
  harness walking every preset's forms with `→`, `←`, `Enter`.

### Layout

- **`frame.rs` owns the characters, `layout.rs` where they go.** One
  composer for every shape: `Layout::lines` → `row_columns` (`frame_plan`,
  `frame_row`, `row_body`) → `wrap_frame` or `box_lines` (the only box
  drawer; `fit_title` places titles). Measure a row's height at the width
  it is laid out to. `Fit::sides` says which column ends touch a box side;

## The repository is not the user's file

garnish runs git on a *timer* in whatever directory the payload names,
which may be an unpacked archive. Rules:

- **Path rule, not name rule.** Every ref read goes through
  `git::read_ref_file` (resolved path stays inside the git directory;
  `git::joinable_ref` keeps `..` out). Every file under `.git` goes through
  `claude_settings::read_regular` (regular, capped, opened `O_NONBLOCK`,
  re-checked after open). `.git/config` streams 64 KiB at a time and skips
  other sections unparsed (`bench/run.sh` `warm-bigconfig` gates it). A
  `gitdir:`/`commondir` counts only if git would call it a git directory.
  A symbolic ref points only under `refs/` or at a capitalised pseudo-ref.
- **Every git call clears what it can.** `run_git` adds `-c
  core.fsmonitor=`, runs `git` from an absolute `PATH` entry only, removes
  `GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE` and kin, sets
  `GIT_NO_LAZY_FETCH=1` and (all but `fetch`) an empty
  `GIT_ALLOW_PROTOCOL`. Nothing on the worker path hashes worktree content
  (no `status`, porcelain `diff`, `add`): `is_dirty` is `diff-index
  --cached` + `diff-files` with `core.checkStat=default`. Do not pin
  `core.trustctime`. `fetch` passes `--upload-pack git-upload-pack`,
  `--no-auto-maintenance`, `--recurse-submodules=no`, the remote after
  `--`, and a failing `SSH_ASKPASS`. What `fetch` still reaches
  (`core.sshCommand`, hooks, credential helpers, …) needs the opt-in
  `fetch_interval` and is an open decision in `PLAN.md`.
- **Cached strings from outside are bounded and plain**
  (`cache::bounded_text`, `MAX_ERROR_CHARS`), including `fetch_error`.
- **A stored stamp in the future means the clock moved**, never "very
  recent": `Entry::is_fresh`, `lock_is_live` and `fetch_attempt` treat it as
  overdue.

## Cache and worker invariants

- A lock file always holds `pid epoch_ms`; it is created by `hard_link` from
  a pre-written temp file and re-stamped by `rename`, never truncated.
- A lock younger than `LOCK_GRACE_MS` is live regardless of pid.
- Only Linux hands the lock to the worker (`--lock-held`, `/proc/<pid>`
  liveness); elsewhere the worker takes it.
- **A failed entry is fresh for its TTL.** Making failure "not fresh"
  spawns a worker every tick.
- Entries carry the situation they were computed for (`head`, `upstream`);
  a validator passed to `Ctx::cached` makes a branch switch a miss and
  must accept a failed entry.
- `Cache::write` stores a failed entry when the value would not read back
  or is over 64 KiB (else it is a miss, and a worker, every tick).
- `refresh = 0` only for payload-only modules, which take only 0.
- GC compares mtimes with the wall clock, runs when a worker writes a
  scope's first entry (never on the tick) and removes only garnish-named
  files, never through a link.
- Temp files: unlink, then `create_new` (`cache::create_fresh`,
  `cache::create_private_dir`). The fallback root `garnish-<uid>` is 0700
  and refused when it is a link, writable by others or not ours.
- `render::render` is the only render that builds its clock from the
  environment; everything in-process takes a `Clock`. Docs and in-process
  tests use `Clock::fixed()`. On the render path the settings chain is read
  once per tick through `Ctx::settings()`, only when needed.
- In the bench a seeded entry is judged by the reader's TTL: a new cached
  module needs seeding in `benches/tick.rs` and a long `refresh` in
  `warm()`.
